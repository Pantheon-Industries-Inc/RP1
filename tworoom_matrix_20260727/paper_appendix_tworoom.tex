The critic is a metric residual network, i.e.\ a learned quasimetric
\begin{equation*}
  d_\psi(\hat z_i \to \hat z_j)
  = \lVert u(\hat z_i) - u(\hat z_j)\rVert_2
  + \max_k \mathrm{ReLU}\bigl(v(\hat z_j)_k - v(\hat z_i)_k\bigr),
\end{equation*}
with $u,v$ the symmetric and asymmetric halves of one $128$-d embedding:
non-negative and triangle-inequality-obeying by construction, so long
distances compose out of short transitions.

\paragraph{Caches.}
Critic training uses a stride-$1$ latent cache so $n$-step targets see every
transition; planner rollout contexts use stride $5$ (one latent per action
block). Single-token caches are $696$ MB. DINO-WM at full width over all
frames would be $284$ GB, so its cache is capped at $200{,}000$ rows
($58$ GB) at full width---a contiguous prefix, $\approx$ episodes
$0$--$2{,}170$, so its learned rows are fit on about a fifth of the corpus.
A $1024$-d random projection works for the critic (its wrapper dispatches on
width) but not for the planner, which bakes latent width into its input
projections. Hardware: $4\times$H100 80 GB.

\paragraph{Deviations and caveats.}
\begin{itemize}\itemsep1pt \parskip0pt \topsep2pt
  \item \textbf{Critic not held fixed.} Section~\ref{sec:theoretical-results}
    treats the critic as fixed during planner training; the reported runs
    warm-start it from the TD solution and co-train it. The optimality
    statement is conditional on the critic and unaffected; the numbers
    correspond to the co-trained variant.
  \item \textbf{Refiner input is wider than the stated interface.} Each plan
    token carries $[\mathbf a_k^{(t)}, \nabla_{\!\mathbf a_k^{(t)}}V,
    \mathrm{proj}(\hat z_t), \mathrm{proj}(\hat z_g\!-\!\hat z_t)]$ plus
    positional and per-iteration embeddings---also the current and goal
    latents, not only the scalar value and its gradient.
  \item \textbf{Critic train/deploy mismatch.} Fit on triples drawn from
    encoder latents, deployed scoring \emph{predictor} outputs against an
    encoder goal; benign only insofar as predictions stay in encoder space.
  \item \textbf{MPPI untuned.} No plan-time MPPI config ships with the
    reference implementation; ours mirrors CEM with the class-default
    temperature, never swept. Those rows are a lower bound and support no
    claim.
  \item \textbf{DINO-WM Adam ran one environment per solver call} (others
    ten): $\approx\!0.27$ GB per retained candidate over a $\approx\!25$ GB
    base puts $200$ candidates at $78.5$ GB. Environment chunking does not
    change the algorithm but does change the random realisation.
  \item \textbf{No held-out split.} Every learned component is fit on
    latents from the episodes the evaluation draws tasks from
    (Section~\ref{sec:tworoom}, Limitations).
  \item \textbf{$a_{\max}$ selection not used.} A sweep
    ($a_{\max}\!\in\!\{2.2,2.8,3.5\}$, $K\!\in\!\{8,12\}$) picked $2.8$ for
    PLDM on task seed $42$ alone; all reported cells use the canonical $2.2$.
\end{itemize}

\paragraph{Reproduction.}
Three details changed measured outcomes materially. \textbf{(i)}~Our runner
$z$-scores cached observation keys and DINO-WM's encoder applies its own
proprioception statistics, fit from the same data; applying both maps every
agent position to ${\approx}{-}3\sigma$ (positions $2$ px apart become
identical to three decimals). Passing proprioception through unnormalised on
that model alone moves $h25$ from $36.0$ to $100.0$. Only DINO-WM consumes
proprioception. \textbf{(ii)}~The renderer is CPU-bound; uncapped BLAS
threads cost ${\approx}40\times$ wall-clock, so they are capped at
$12$--$16$. \textbf{(iii)}~The released single-token encoders use a
pre-$5$.x Hugging Face ViT layout; converting under the wrong major version
has \texttt{load\_state\_dict} reject all $192$ encoder tensors. Reference
environment: torch \texttt{2.4.1+cu124}, transformers \texttt{4.57.6},
Python \texttt{3.11.10}.
