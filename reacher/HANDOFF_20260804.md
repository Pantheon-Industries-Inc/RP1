## 3. Configuration (the reported numbers)

**Protocol.** `horizon=5` blocks, `action_block=5` (frameskip) so one plan is 25
primitive steps; `receding_horizon=5` — the whole plan executes before
replanning, 2 planning cycles per 50-step episode. This matches LeWM appendix D
and DINO-WM. `eval.num_eval=50` episodes/cell, `eval.img_size=224`,
`goal_offset_steps=25`. Selection seeds 50–51 for every hyperparameter choice,
never reported; reporting seeds 42–47.

**Metric.** held-at-end: every joint within tau of the goal *at the final step*.
Stricter than the released code's latched convention. tau=0.1 headline, 0.05 also
reported. The eval emits **only** held-at-end — there is no latched metric in
this harness, so paper-comparable latched numbers would need adding.

**Shared value (critic)** — used by Value+CEM, Value+Adam, and as the init of
both RLP and PWM: 3-frame window quasimetric (MRN head), `window_lag=5`,
declared `latent_dim=576` (=3x192), expectile 0.05, **gamma 0.98**, n-step 50,
6000 steps, batch 1024, `p_cross=0.3`, seed 0, trained on the full fs1 cache.
Critic data is cached transitions only (`expand-weight 0`) for both RLP and PWM —
no learned component ever sees environment interaction.

**RLP.** Shared: arch v4, gamma 0.98, expectile 0.1→0.03, critic-lr 1e-3→1e-4,
replay-prob 0.5, expand-weight 0, n-step 50, **1000 steps**, batch 128, iters 8,
horizon 5, max-delta 12, uniform lambda, `--pad-context`.
Per base: LeWM (amax 2.2, actor-lr 1e-4→1e-5, mean-weight 0.3), PLDM (amax 1.8,
3e-4→3e-5, 0.5). Training seeds 0–5.
Actor arch `[ckpt]`: width 256, hidden 512, layers 2, s_dim 256, goal_mode
`diff`, cond_mode `token`, head_mode `gate`, iter_mode `scalar`, s0_mode `zero`,
`use_grad=True`, use_gate/use_z0/use_zg/feat_norm/pre_ln all False.

**PWM.** terminal objective, 1000 steps (budget-matched to RLP), width 512,
layers 3, actor-lr 5e-4→5e-5, EMA tau 0.005, seeds 0–2. `objective=terminal` and
`gamma=0.98` are `[ckpt]`-verified.

`mean_weight` averages the terminal cost over **refinement iterations k**, not
rollout timesteps — RLP has no per-timestep path term.

## 5. OPEN: the rh=1 ablation

**Motivation.** rh=5 executes 25 steps open-loop. DINO-WM ("the first k
actions... then repeats at the next time step"), PLDM ("re-plans at every k-th
interaction... k=1") and stable-worldmodel ("the K first actions are executed")
all replan after a short chunk, so an rh=1 row strengthens the compute claim.
rh=5 remains the headline (LeWM app. D).

**Done: 16 actors retrained for rh=1** (`run_rh1_retrain.sh`), 6000 steps, one
seed each, screened-on-selection-seeds design. Grid: 4 alignment modes x
amax{1.8,2.2} x 2 bases. `--align-mode` was added to `train_lip_ac.py`
(`patch_align_modes.py`); defaults `terminal`/weight 0 keep behaviour
bit-identical, and all four modes smoke-tested identical at step 0.

| mode | adds to the loss | rationale |
|---|---|---|
| `terminal` | — | control; isolates the 6000-step change |
| `dense` | `sum_t gamma^t V(z_t,z_g)` | PWM's dense-vs-terminal was +16.8/+64.9 |
| `prefix` | `V(z_1,z_g)` | the chunk rh=1 actually executes |
| `randhorizon` | `V(z_h,z_g)`, h~U{1..5} | every prefix must land |

Training `E_final` (a LOSS, not a score — these decouple badly on this task):
dense 1.007–1.171, terminal 1.090–1.185, prefix 1.379–1.396, randhorizon
4.097–4.369 (expected: it scores a random prefix, a different quantity).

**BLOCKER: I3 does not execute.** The intended readout is: fixed clock until the
plan would overshoot the deadline, then score the best still-reachable chunk —
`cost = min_j V(z_j, z_g)` for `j <= min(H, chunks_remaining) - 1`, with
`chunks_remaining` from the policy's step counter. At rh=1 the executed length is
1 chunk regardless, so `min(rh, j*+1) = 1` and **I3 is purely a cost-readout
change** — nothing inside RLP's refinement needs to change. At rh=5 with
budget 50 it provably never fires (50 = 2 x 25).

Implemented in `patch_i3_argmin_prefix.py`: `policy.py` publishes
`model.i3_chunks_remaining` before each solve (gated on `plan_config.deadline`),
and the metric hook in `eval_wm.py` takes the argmin. **It never runs.** A debug
print placed inside the hook's `elif _m >= 3:` branch produced no output on a
LeWM cell using `l2window3.pt` — a 576-wide metric on a 192-d latent, which
should give `_m = 3`. Four successive edits (attribute owner, frame axis, debug
print) were all to code that never executes.

**NEXT STEP — one diagnostic, not another edit.** Print `_m`, `pred.shape`,
`self.metric_in`, `_D` **unconditionally at the entry of `_MetricCost.get_cost`**
(`eval_wm.py` ~line 221), not inside any branch, for a LeWM run with
`l2window3.pt`. That settles whether I3 belongs in the `_m >= 3` branch at all.

> **This has an implication beyond I3.** If the 3-frame window metric does not
> reach the cost through the `_m >= 3` branch, then the reported 3-frame numbers
> were computed through a path not yet located. Worth confirming on its own.

**Symptom to watch for:** I3 not firing yields scores *identical to unaligned*
(42.0 / 86.0), which look like a legitimate result. Always confirm an `[I3]` line
appears before trusting any rh=1 number.

**Measured rh=1 reference points** (RLP lejepa s0, seed 42, single cell):

| variant | @0.05 | @0.1 |
|---|---|---|
| rh=5 (reported) | 66.0 | 100.0 |
| rh=1 + commit-whole-plan-at-deadline | 58.0 | 100.0 |
| rh=1, no alignment | 38.0–42.0 | 86.0 |

So the "replanning hurts" appearance was **misalignment, not feedback**: a
terminal cost optimising step 70 while graded at step 50. I3 should beat both.

Partial full-table rh=1 numbers (aborted, unequal n, **not quotable**): RLP
92.8 (n=36) / 94.3 (n=36) but Latent+CEM 58.3 (n=6) / 51.0 (n=2) — samplers
appear to collapse under frequent replanning while RLP is near-invariant. If real
this *widens* RLP's margin, which is exactly why it needs full n before use.

## 6. OPEN: DINO-WM (parked)

Third base, `dinowmnp` = **pixels-only** (`proprio: 0` tensors in the raw
checkpoint — verified). The paper's reacher DINO-WM figure (79) is a
proprio-conditioned re-implementation; **this artifact cannot reach it**, and the
prior campaign independently measured 65.3.

Done: converted (`convert_reacher_bases.py --only dinowmnp`, parity gate passed,
version-invariant — 4.57.6 and 5.14.1 give bit-identical weights); 92 GB dataset;
**563.6 GB full-width fp32 cache complete** (`CACHE_EXIT=0`, 2.01M x 75,264, no
compression); 1-frame value trained and verified (`latent_dim 75264, frames 1`).

**1-frame Latent+CEM bar: 62.0 @0.1 / 27.0 @0.05** (seeds 42–43, 224 px).

**Blocker: RLP OOMs.** 139.8 GiB H200, fails on a 20 MiB alloc with 13 MiB free.
Batch 128 → 8 barely helped, so it is the 8-iteration autograd graph over 5-step
rollouts at 588 tokens/forward, not the batch. Three options, none free:
reduce `--iters` to 4 (cheap, but the row is then depth-4, not depth-matched;
TwoRoom evidence says K=8→4 is near-free); detach between refinement iterations
(changes what RLP *is*); or report DINO with CEM/Adam only and no RLP row.

Settled negatives for DINO: image resolution is irrelevant (196 and 224 score
identically, 52.0 both); 1-frame beats 3-frame by 6 points (58 vs 52), consistent
with DINO-WM's own 1-frame cost; transformers version is irrelevant.

Note `img_size=196` in its config with `interpolate_pos_encoding=True` — the WM
resizes internally, so 224 input is correct and keeps eval consistent with the
cache. Also `keep_pred_frames` defaults to **2** and was set to 3 in
`config.json`; a re-conversion overwrites `config.json` and silently reverts it.

## 7. Ops gotchas that cost real time

**Rebuild after a container recycle** (`/workspace` survives, pip env does not):
`libegl1 libopengl0 libgles2 libglvnd0 libgl1` via apt (PyOpenGL reports
`PLATFORM.EGL = None` without them); `pip install -e swm_cem` with torch
**constrained** to 2.6.0+cu124 from the explicit cu124 index — the `swm[env]`
extra otherwise upgrades torch to 2.13 and leaves cu13 wheels shadowing cuDNN;
then h5py, hdf5plugin, transformers==4.57.6, timm, scipy, imageio,
**imageio-ffmpeg** (without it every eval exits nonzero *after* scoring, on video
write), stable-pretraining, mujoco==3.10.0, dm_control==1.0.43, zstd (apt).
Verify with a live `nn.Conv2d` on GPU and one regression eval.

**Failures that masquerade as results** — this campaign produced five:
1. `meanof`'s `held10` parse returned the `10` from its own key name → every
   @0.1 mean printed a constant `10.0`.
2. Concurrent sampling-solver evals core-dump under GPU contention (six
   occurrences); a crashed arm averaged to `0.0`, indistinguishable from total
   failure. Cap at ~4 concurrent; re-run serially; **always print how many seeds
   scored**.
3. `deque(maxlen=flatten_receding_horizon)` would have silently dropped 20 of 25
   committed actions — a crash exposed it by luck.
4. A bootstrap printed `BOOT2_DONE` after `tar` had already failed (no `unzstd`).
5. I3 not firing returns the unaligned baseline verbatim.

Treat any unaudited `0.0` or `10.0` in older logs as a suspected defect.

**Other traps:** `torch.save` of a large cache gets ~20 MB/s on the DINO pod's
network volume (605 GB ≈ 9 h) while a single buffered write benchmarks at
301 MB/s — benchmark the *pattern*, not the device. `eval_budget` is in primitive
steps and must be ≥ `horizon x action_block` = 25. `--wm` must be an absolute
path or the loader falls through to HF and finds an empty cache dir. Killing by
`pkill -f <pattern>` self-matches your own ssh command line — list PIDs in one
call, kill by number in a second. Write patch scripts locally and `scp` them;
heredocs over ssh break on apostrophes and triple quotes.

**The patched source lives only on pod volumes.** The repo's
`stable-worldmodel/` has no `_wpair`, no `pad_context`, and no
`train_window.py`. Losing both pods loses the trainers. Committing that tree is
overdue.

## 8. Corrections carried forward (things previously believed and now known false)

- The in-code claim that rh=5 matches "the LeWM paper's entire optimized action
  sequence is executed before replanning" **is** supported — LeWM appendix D. An
  earlier search of the main text only appeared to contradict it.
- RLP's critic never trains on actor-visited states (`expand-weight 0`), so a
  co-trained critic is just the same TD fit with more steps on the same cached
  data — it is not "adapted to the actor's distribution".
- The value is **not** step-limited: 25x more training steps moved TD+CEM not at
  all, though the loss did fall.
- gamma is a sharp peak at 0.98 (0.97 → 95.0, 0.99 → 96.3, 0.95 → 81.7 on
  selection seeds); the whole stack was undiscounted before 2026-08-02.
- The window is worth 8–22 points and helps the *parameter-free* bar too, so it
  is a property of the cost, not something only RLP exploits.
- Dyna inverts the margin (helps Latent+CEM to 53.0/86.3, hurts RLP to
  30.0/75.1 over 5 seeds) — excluded, and the only experiment that touched the
  environment.
