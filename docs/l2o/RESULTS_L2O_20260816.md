# L2O-MPC baseline campaign — 2026-08-15/17

L2O-MPC (Sacks & Boots, *Learning to Optimize in Model Predictive Control*,
ICRA 2022, [arXiv:2212.02603](https://arxiv.org/abs/2212.02603)) ported as
`model=l2o` / `core/solver=l2o`. Method, paper-component map, and the list of
deliberate deviations: [README_l2o.md](README_l2o.md).

## Shared protocol

DAgger imitation (`beta_k = 0.8^k` over 20 rounds) of an MPPI expert with
N = 512 samples, computed through the frozen world model against the frozen
`value_td` critic; the learner uses M = 64 samples × K = 4 iterations = **256
forward unrolls per decision**, matching DMPO's deployed budget so the two
learned-optimizer rows differ in method, not compute. Nothing is trained on
environment interaction: the expert is pure computation, and DAgger's state
distribution is the inner-loop iterate chain on offline cache windows.

Three optimizer seeds per cell, report draws 42/43/44, 50 episodes each. Cube
and Reacher are held out (train episodes 0–7999, eval draws 8000–9999); TwoRoom
follows the shipped full-pool contract (training and evaluation share the
authors' 10,000-episode pool, so those rows are formally upper bounds — the
within-table comparison is unaffected because every planner draws from the same
pool). `amax` is inherited per cell from the matched RLP/DMPO configuration,
never tuned: Cube 1.6/4.5, TwoRoom 2.5, Reacher 2.2/1.8.

In-cell value-MPPI controls (same critic, 9,000 rollouts) were run for h25
draw 42 on Cube/TwoRoom and draws 42/43 on Reacher, then dropped to save
wall-clock; the prior campaign's protocol-matched MPPI rows are quoted
alongside and agree with them to 1–3 points.

**Hyperparameters were not swept.** Every value is the paper's published
setting (Adam 1e-3, dropout 0.1, 20 DAgger rounds, Halton samples, fixed
diagonal covariance, expert N ≫ learner M); the two repo-side knobs (`amax`,
the 64×4 budget) were inherited rather than tuned. That is deliberate for a
baseline — a swept L2O against unswept siblings would flatter it — but it
scopes the Cube result to "at paper hyperparameters".

## OGBench Cube (success %, h25 / h100)

Horizons: h25 = `goal_offset_steps=25 budget=50`, h100 = 100/200.

| planner | LeWM | PLDM |
|---|---|---|
| **L2O-MPC** | **64.4 ± 6.0 / 50.0 ± 3.3** | **58.9 ± 0.8 / 45.3 ± 0.5** |
| in-cell value-MPPI (h25, draw 42 only) | 64.0 / – | 68.0 / – |
| latent CEM (replication table) | 78.0 / – | 62.7 / – |
| RLP | 86.9 / – | 82.0 / – |
| no-op floor | 54.0 | 54.0 |

Per-seed h25 means — LeWM 68.7 / 56.0 / 68.7, PLDM 58.7 / 60.0 / 58.0.

**Cube is L2O-MPC's failure mode.** Parity with the MPPI it imitates on LeWM
(64.4 vs 64.0), *below* it on PLDM (58.9 vs 68.0), both under latent CEM and
~10 points over the no-op floor. The training signal says why: cube's DAgger
imitation loss *rose* as beta decayed (0.57 → 0.87 on seed 0), i.e. the learned
update never fit the learner's own iterate distribution in cube's
125-dimensional plan space at the paper's hyperparameters. LeWM's ±6.0 seed
spread is the campaign's largest, consistent with a partially-fit optimizer.
The paper's own escalation for harder tasks — hidden 2048/4096 instead of
1024 — is the natural follow-up arm and has not been run.

Provenance: jobs 7035/7037 (+ 7146/7147, shards 7285/7286), tags
`l2o-cube-{lewm,pldm}-20260815`.

## TwoRoom (success %, h25 / h100)

Evaluated on the authors' fetched pool (`tool=fetch_dataset dataset=tworoom`)
through the `tworoom_*_h5` eval roots.

| planner | LeJEPA | PLDM |
|---|---|---|
| **L2O-MPC** | **95.8 ± 1.4 / 90.9 ± 2.5** | **95.1 ± 0.8 / 48.2 ± 1.3** |
| in-cell value-MPPI (h25, draw 42 only) | 90.0 / – | 86.0 / – |
| value MPPI (replication table) | 87.3 / 64.0 | 78.7 / 58.7 |
| value CEM (replication table) | 100.0 / 96.0 | 100.0 / 89.3 |
| latent Adam (replication table) | 94.7 / 24.0 | 90.7 / 42.0 |
| RLP | 100.0 / 94.2 | 98.2 / 96.0 |

Per-seed means — LeJEPA h25 94.0/97.3/96.0, h100 88.0/90.7/94.0;
PLDM h25 95.0/92.0/92.0, h100 47.3/47.3/50.0.

**LeJEPA h100 is the campaign's headline cell: 90.9 against value-MPPI's
64.0** — +26.9 points at 35× fewer rollouts, and within ~3 points of RLP's
94.2. This is the clearest case of the paper's claim transferring: a learned
update rule, imitated offline from a many-sample expert, retains that expert's
quality at a fraction of the search budget. The h25 cells confirm it more
modestly (+5.8 LeJEPA, +9.1 PLDM over the in-cell control), where the ceiling
leaves little room.

**PLDM h100 collapses to 48.2 while LeJEPA holds at 90.9.** The critic is not
the cause: value-CEM reaches 89.3 and RLP 96.0 on that same base with the same
critic family. What differs is the search budget — 256 samples versus CEM's
9,000 — and PLDM's long-horizon landscape punishes it specifically, which its
latent-objective rows (33–52 at h100) independently show.

Provenance: jobs 7036/7038 (+ 7148/7149 and per-(draw, seed) shards
7236–7250), tags `l2o-tworoom-{lejepa,pldm}-20260815`.

## Reacher, first-hit h25 (success %, tau = 0.1 / tau = 0.05)

Protocol caveat: the earlier Reacher tables in this repository report draws
42–47; everything here is 42–44.

### Window-3 critic (protocol-matched: window quasimetric, e0.05, lag 5)

| planner | LeJEPA | PLDM |
|---|---|---|
| **L2O-MPC** | **93.3 ± 1.1 / 74.9 ± 2.3** | **94.7 ± 0.0 / 77.3 ± 1.4** |
| in-cell value-MPPI (draws 42/43) | 85.0 / 66.0 | 87.0 / 64.0 |
| value-w3 MPPI (replication, 6 draws) | 86.0 / 66.0 | 83.7 / 61.7 |
| value-w3 CEM (replication) | 99.3 / 89.3 | 98.3 / 84.7 |
| latent-w3 CEM (replication) | 99.0 / 94.3 | 98.3 / 89.3 |
| RLP | 99.9 / 97.1 | 99.4 / 91.2 |

**L2O-MPC beats the MPPI it imitates in all four cells** (+7 to +13 points) at
35× fewer rollouts, and the ruler is calibrated: the in-cell controls
(85.0/66.0, 87.0/64.0) agree with the prior campaign's independent six-draw
rows (86.0/66.0, 83.7/61.7) to within 1–3 points. Seed variance is remarkably
small — PLDM tau=0.1 is **exactly 94.7 on all three seeds** — which follows
from imitating a deterministic expert.

### Window-1 ablation

Identical recipe with a single-frame critic; `amax` held at 2.2/1.8 so the
critic window is the only difference.

| planner | LeJEPA | PLDM |
|---|---|---|
| **L2O-MPC, window-1** | **90.9 ± 2.6 / 69.6 ± 2.2** | **89.3 ± 2.7 / 60.9 ± 1.7** |
| L2O-MPC, window-3 (above) | 93.3 ± 1.1 / 74.9 ± 2.3 | 94.7 ± 0.0 / 77.3 ± 1.4 |
| *window-1 penalty* | *−2.4 / −5.3* | *−5.4 / −16.4* |
| value-w1 MPPI (App C.3 replication) | 74.0 / 42.0 | 60.0 / 38.7 |
| value-w1 CEM (App C.3 replication) | 97.3 / 82.0 | 96.0 / 76.0 |

**(a) The penalty is tolerance-dependent** — 2–5 points at tau 0.1 but 5–16 at
tau 0.05: the signature of a critic that cannot represent arrival velocity
(hitting a target loosely tolerates a bad approach; hitting it tightly does
not). The RLP window ablation found the same mechanism (~+9 for window-3 at the
tight tolerance). PLDM is hit hardest, as it is wherever information is reduced.

**(b) L2O's margin over its expert *widens* under the weaker critic** —
+27.6/+22.2 at tau 0.05 versus +8.9/+13.3 at window-3. DAgger fits the learned
update to whatever cost it is handed, so it degrades more gracefully than the
fixed MPPI reduction. Both w1 jobs trained cleanly (imitation loss 0.58 → 0.05
LeJEPA, 0.34 → 0.07 PLDM), so this is not an underfitting artifact.

Provenance: window-3 jobs 7040/7041 (+ 7150/7151), tags
`l2o-reacher-{lejepa,pldm}-20260815`; window-1 jobs 7342/7343, tags
`l2o-reacher-{lejepa,pldm}-w1-20260816`. The public Reacher h5 pads every
episode's terminal step with NaN actions; the shared `WindowSampler` is
nan-aware, which is why these runs trained rather than silently producing NaNs.

## Wall-clock speed (OGBench Cube / LeWM, 1×H200, fp32)

Whole-decision means (encode + plan + select), each solver timing its own
`solve()`, planners run sequentially on one node, warmup dropped per process.
Harness [scripts/sky/planner_speed.yaml](../../scripts/sky/planner_speed.yaml).

| planner | rollouts/decision | mode | B=1 | B=50 | B=50 per env |
|---|---|---|---|---|---|
| **L2O-MPC** | 256 fwd | graphed | 45.3 ¹ | 188.3 | 3.77 |
| L2O-MPC | 256 fwd | eager | 88.0 | 232.5 | 4.65 |
| **RLP / LIP** | 9 fwd + 8 bwd | graphed | ~30 ² | ~79 ³ | 1.58 |
| RLP / LIP | 9 fwd + 8 bwd | eager | 304.7 | 333.3 | 6.67 |
| **DMPO** | 256 fwd | eager (its best) | 83.3 ⁴ | 236.3 ⁴ | 4.73 |
| DMPO | 256 fwd | graphed | 126.4 ⁴ ⚠ | 916.6 ⁴ ⚠ | 18.33 |
| CEM | 9,000 fwd | eager | 390.6 ⁵ | 5,308.2 ⁵ | 106.2 |
| MPPI | 9,000 fwd | eager | 420.3 ⁵ | 10,020.3 ⁵ | 200.4 |
| Adam | 3,000 fwd + 3,000 bwd | eager | 959.3 ⁵ | 17,129.8 ⁵ | 342.6 |

¹ Median 30.9; the mean-vs-median gap is **encode** variance, not planning —
L2O's plan phase measured 21.0–21.2 ms across every decision (job 7771).
² From the 2026-08-12 audit (job 4840); this campaign's own RLP graphed B=1
samples were capture-contaminated (RLP terminates early at B=1, yielding 5–6
decisions, so one capture dominates) and are not used.
³ Steady state; the measured mean was 374.4 because a shrinking eval batch
re-captures.
⁴ Measured by the DMPO campaign, not here. ⚠ DMPO's graph capture *regresses*
its wall-clock, unlike L2O's.
⁵ Under the **learned-value objective** (`core/value=metric`), so each sampled
rollout also pays a critic forward; the audit's latent-objective CEM was
241.9 ms eager / 218.6 graphed. The samplers have no graphed path in this tree.

Calibration: the repo's published benchmark table lists 1-env wall-clock of
0.42 s (CEM) and 0.38 s (MPPI) against 0.391 / 0.420 measured here, so this is
timing the same quantity those numbers did.

**Reading.** RLP is fastest at both batch sizes once graphed (~30 / ~79 ms).
L2O's 256 rollouts cost only ~1.5× RLP's 17 at B=1 because rollout *count* is
the wrong currency: L2O's 64 plans are scored as one batch, so a decision is
~25 sequential world-model calls against RLP's ~85 (8 iterations of forward
*and* backward), and a call on 64 rows costs only ~1.6× a call on one row at
this model size. RLP also scales better with batch (2.6× from B=1 to B=50 vs
L2O's 4.2×) because its work stays one row deep while L2O's rows multiply to
3,200.

**CUDA-graph capture** (`core.solver.graphed=true`) for L2O is a plain
`CUDAGraph` replay, not LIP's `make_graphed_callables`: the decision is a single
fixed shape, forward-only, no gradient. `graphed=verify` measured
**max_deviation 0.000e+00** at B=1 and B=50 — bit-exact, where LIP's capture
(which must also record a backward) lands at 5.96e-8. Capture costs seconds per
distinct row count and a shrinking eval batch triggers fresh captures, so
graphed *means* over a full eval run exceed steady state.

Speed provenance: jobs 7739 / 7765 / 7766 / 7768 / 7769 / 7771.

## Campaign-level findings

1. **The paper's claim replicates where the search landscape is benign.**
   L2O-MPC beats the 9,000-rollout MPPI it imitates at 256 rollouts on TwoRoom
   (h25 both bases; LeJEPA h100 **90.9 vs 64.0**) and in all four Reacher cells
   (+7 to +13).
2. **It never overtakes CEM or RLP.** Ordering across all three environments:
   RLP > CEM > L2O ≥ MPPI.
3. **Cube is the honest failure mode** — parity with MPPI on LeWM, below it on
   PLDM, with a DAgger loss that rose as beta decayed.
4. **TwoRoom PLDM h100 collapses (48.2) while LeJEPA holds (90.9)**, and
   value-CEM's 89.3 on the same base and critic shows the binding constraint is
   the 256-sample budget, not the objective.
5. **Seed variance is tiny** (Reacher PLDM tau=0.1: identical on all three
   seeds) — imitation of a deterministic expert, unlike RLP's actor-seed spread.
6. **A weaker critic hurts L2O less than it hurts MPPI** (Reacher window-1
   ablation): the learned update adapts to the cost it is trained against, so it
   loses least where the *objective* is degraded and most where the *search* is
   hard.
7. **Speed: RLP is fastest once both are graphed** (~30 vs 45.3 ms at B=1), but
   L2O's 256 rollouts cost only ~1.5× RLP's 17 because wall-clock follows
   sequential depth, not rollout count. L2O's capture is bit-exact; DMPO's
   regresses.
