## 1. The two headline results from this session

### (a) `amax` 1.6 is the real win — +7.1 pts, and it kills the seed collapse

45-eval sweep, 3 seeds × 3 draws. Broad **flat plateau 1.4–2.2** (85.6 / 86.4 /
86.2 / 85.8 — a 0.8-pt range), both tails falling off:

| amax | 3-seed | seed spread |
|---|---|---|
| 1.0 | 79.3 | 3.3 |
| 1.2 | 82.4 | 4.0 |
| 1.4 | 85.6 | 4.7 |
| **1.6 (adopted)** | **86.4** | 4.7 |
| 1.8 | 86.2 | 6.7 |
| 2.2 | 85.8 | 4.7 |

**The variance is the story, not the mean.** Seed spread collapses 20.7 → 4.7 and
the catastrophic-seed mode (seed 0 = 68.0 at amax 3.5) disappears entirely.
amax tuning is now exhausted. Within-plateau ordering is single-cell noise — 1.4
sits below 1.6 only because of one cell (seed 1, draw 44 = 68 vs 78).

### (b) Dyna, properly controlled, is **+4.7 and significant** — but only with adequate data

Episode-disjoint, matched amax 1.6, held-out episodes 8000–9999, egl. Both POST
arms share the PRE arm and identical collection seeds.

| seed | PRE | POST-thin (K=87) | POST-full (K≈18) |
|---|---|---|---|
| 0 | 88.7 | 92.7 (+4.0) | 92.7 (+4.0) |
| 1 | 86.0 | 90.7 (+4.7) | 92.0 (+6.0) |
| 2 | 88.7 | 88.0 (**−0.7**) | 92.7 (+4.0) |
| **3-seed** | **87.8** | **90.4** | **92.4** |
| **Δ vs PRE** | — | **+2.7** ± 1.68, t=1.59, p≈0.25 | **+4.7** ± 0.67, **t=7.00, p≈0.02** |
| seed spread | 2.7 | 4.7 | **0.7** |

**Dyna is real: +4.7, all three seeds positive, p≈0.02.** It also collapses seed
spread 2.7 → **0.7**, i.e. it makes the planner not just better but far more
reproducible.

**The duplication mattered, and the two-arm design was necessary.** `full − thin`
= **+2.0**. On thin data the effect was +2.7, insignificant, and *negative on seed
2* — indistinguishable from "Dyna does nothing." Fixing only the collection

conclusion would have been wrong.

**The old "+11.4" (83.0 → 94.4) is still retracted as a controlled claim** — it
mixed the fine-tune with an amax change worth ~7 pts *and* collected on-policy
rollouts from the eval pool. The honest, fully-controlled effect is **+4.7**.

Caveat: n=3 seeds, so p≈0.02 rests on a df=2 t-test with a very small SD. The
consistency (+4.0/+6.0/+4.0) is what carries it; more seeds would firm it up.

## 2. Why there are two POST arms (the duplication problem)

The WM needs a 25-frame window (span 20 + frameskip 5), so on-policy episodes
under 25 steps are structurally unusable and get dropped. With
`terminate_at_goal=True` and an ~88 %-success actor, **the successes are exactly
the episodes that end early** — so the filter discards successes and keeps
failures:

| | arm 1 "thin" | arm 2 "full" |
|---|---|---|
| `world.terminate_at_goal` | True (default) | **False** |
| episodes kept | 407 of 1800 (22 %) | **1800 of 1800** |
| on-policy rows | 18,500 | **90,000** |
| duplication K for 50/50 | **87** | **18** |
| r1 reference | — | K=25 ✓ same regime |

Arm 1's K=87 means ~10k distinct on-policy windows seen ~174× over two epochs — a
memorisation risk that would make a null uninterpretable. Both arms use
**identical collection seeds**, so `full − thin` isolates the
duplication/termination effect rather than a data reshuffle. The PRE arm is shared.

## 3. Validity: the split, and what it did (and didn't) show

There was **no train/eval split anywhere** in this stack — v2WM, the fs1/fs5
caches, the TD teacher, the LIP actor-critic, Dyna collection and the WM
fine-tune all used all 10,000 episodes of `ogb_cube_single.lance`, and
`eval_wm.py` drew its tasks from that same file.

Now enforced for the Dyna control: **train 0–7999 / eval 8000–9999**, strict —
the latent caches are filtered too, so the critic never sees an eval episode.
0–7999 is a *prefix*, so episode ids stay contiguous and `expert_actions.h5` plus
`ep_off/ep_len` bookkeeping keep working with no renumbering. Verified
arithmetically: caches 2,010,000 → 1,608,000 rows = 8000 × 201; eval draw reports
`ep_range 8000:10000 -> 2000/10000 episodes eligible` with 352,000 valid starts =
2000 × 176 exactly.

### The data division, explicitly

Split over the 10,000 episodes of `ogb_cube_single.lance` (201 steps each):
**train = episodes 0–7999 (80 %), eval = episodes 8000–9999 (20 %)**.

| component | episodes used | enforced by |
|---|---|---|
| v2WM base (WM₀) | **ALL 0–9999** ⚠ | not retrained — the one residual leak |
| fs1 latent cache (critic/TD) | 0–7999 → 1,608,000 of 2,010,000 rows | `filter_cache_eprange.py` |
| fs5 latent cache (actor) | 0–7999 → 328,000 rows | `filter_cache_eprange.py` |
| TD teacher | 0–7999 | trained on filtered fs1 |
| LIP actor + critic, **both arms** | 0–7999 | filtered caches |
| Dyna on-policy collection | 0–7999 | `+eval.ep_range=0:8000`, run aborts if not applied |
| WM fine-tune, expert slice | **< 8000** | `build_dyna_mix.py --expert-ep-hi 8000` |
| WM fine-tune, on-policy slice | from 0–7999 rollouts | inherited from collection |
| **evaluation** | **8000–9999 only** | `+eval.ep_range=8000:10000` |

Eval draw: seeds **42/43/44**, `num_eval=50` ⇒ **150 tasks**, goal = frame t+25,
budget 50 steps, success = block within 4 cm. Verified: the draw logs
`ep_range 8000:10000 -> 2000/10000 episodes eligible` and finds **352,000 valid
starts = 2000 × 176** exactly (201 − 25), lowest drawn row 1,642,527 > 1,608,000.

Separately, the **fine-tune mixture** (a different "division" — by rows, not
episodes) is **50 / 50 expert : on-policy**, hit by duplicating the on-policy
rows K times:

| arm | expert rows | on-policy rows | K | effective on-policy frac |
|---|---|---|---|---|
| thin | 1,608,000 | 18,500 | 87 | 0.500 |
| **full** | 1,608,000 | **90,000** | **18** | 0.502 |

**The leak turned out to be empirically negligible.** LIP scored **87.8 held-out
vs 86.5 in-pool** — *better* on episodes it never trained on. So critic
memorisation was never the problem. Earlier session notes overstated it; the
value-gradient ablation (87.6 → 54.0, grad carries ~91 %) says only where a leak
*would* bite, not that one was biting.

**Residual, state it in any writeup:** v2WM itself was pre-trained on all 10k
episodes. Fixing that needs a base-WM retrain on a subset — separate job.

**Also unresolved:** `amax` was selected on the eval draws (~3 pts of optimism at
n=150 over ~6 candidates). `dyna_harness/amax_holdout_select.sh` does honest
select-on-42 / report-on-43-44; it picks 1.4 and reports 86.3 vs the naive 86.4,
so the bias was small *because the plateau is flat* — luck, not method.

## 4. Renderer: egl always

Standing instruction. egl produced the authors' h5 renders, so it is the
in-domain choice. The reacher campaign found osmesa out-of-domain there, worth
**+7.3 pts**. **On cube the two measure equal** — 18 cells:

| amax | egl | osmesa |
|---|---|---|
| 1.6 | 86.5 | 86.4 |
| 1.8 | 86.2 | 86.2 |

So the reacher bug does **not** transfer to cube and the osmesa-era amax card
stands. Do not assume that equality for tworoom/puzzle — those are unchecked.

Requirements: pin `MUJOCO_EGL_DEVICE_ID` (else every render context piles onto
physical GPU 0 regardless of `CUDA_VISIBLE_DEVICES`), and never run evals
concurrently with training (egl crashes) — **serialize, don't switch renderer**.
Bonus: egl evals run **~1.9 min vs osmesa's 3.2** (GPU vs CPU rendering), a
~1.7× speedup.

Completed pre-2026-07-27 scripts still say `osmesa` deliberately — accurate
record of what produced their numbers.

## 5. Open questions, in priority order

1. **Does +4.7 survive more seeds?** p≈0.02 rests on df=2. Seeds 3–5 on PRE and
   POST-full would firm it up; ~2.5 h per arm-seed. This is the highest-value
   next run.
2. **Duplication mattered — ANSWERED.** `full − thin` = +2.0, and thin was
   negative on seed 2 while full is positive on all three. Data volume was the
   binding constraint. Corollary: **a second Dyna round is now worth trying**,
   since more/better on-policy data is demonstrably the lever. Collect with
   `world.terminate_at_goal=False` from the start.
3. **Optimization arms at amax 1.6, never run.** `dyna_harness/lr_sweep_a16.sh`
   is written, deployed and stopped mid-flight (its egl cells are cached; it
   resumes). Motivation: at amax 3.5, `--iters 16` gave the best imagined plans
   ever measured (E_final 1.68 vs 7.82) and planned *worse* (80.0) — textbook
   action-exploitation. At amax 1.6 E_final is only 5.05/4.70/3.71, so
   optimization headroom is unused. If the clip makes exploitation unreachable,
   harder optimization may now be safe. Arms: `it16` (iters 16), `s12k` (12k
   steps), `alr` (actor-lr 1e-4→1e-5).
4. **The TD teacher is a single seed (0), shared by every LIP run.** So the
   "3-seed" cards vary actor/critic init on one common teacher — not fully
   independent replicates, and the reported spread understates true variance.
   Retraining the teacher per seed is cheap (6000 steps ≈ 100 s).
5. **Draw 43 is saturated** (mean 94.1, spread 6 across 15 cells) while draw 44
   does all the discriminating (75.2, spread 24). A 3-draw mean is nearly "draw
   44 plus a constant". Future cards should drop 43 or add harder draws.

## 6. Ops gotchas that cost time this session

- **arch-vs-training `config.json`.** `lewm_expert.py` writes the *training*
  config into its checkpoint dir under the name `config.json`; the loader needs
  the *architecture* config. Copying the checkpoint's one kills `cache_latents.py`
  11 s in with `ConfigAttributeError: Missing key load_state_dict`. Fine-tuning
  does not change architecture — **copy `v2WM/config.json`** (byte-identical, sha
  `fd35a47c`, to how the working r1 run packaged its WM). Fixed in both arm
  scripts, with a validator.
- **`eval.ep_range` existed but was broken.** It shrank `ep_indices` without
  shrinking the dataset, so `max_start_per_row` raised `KeyError` on any excluded
  row — unusable for its only purpose. Fixed (`3fbc6f1`) by masking out-of-range
  rows. **The reacher campaign's "held-out draws" are not held out**: its
  collector passes `ep_range=0:8000` against a 1,024-episode file (keeps
  everything — a no-op) and its eval passes no range at all. Its revised
  headlines (LeWM 76.9→78.2, PLDM 78.8→89.2) still carry the leak. Not fixed
  here; that campaign owns those runs.
- **The Bash tool runs zsh**, which does not word-split unquoted `$var`. This
  silently corrupted a test fixture and broke an `ssh $OPTS` invocation. Drive
  test fixtures with `bash script.sh`; inline ssh options rather than putting
  them in a variable.
- **`timeout`-wrapped children get their own pgid**, so killing a driver's
  process group spares them. Exploited deliberately twice to swap a driver
  without losing hours of training — verify with
  `ps -eo pid,pgid,args` before killing.
- **SSH discipline** (from a previous lockout): poll ≥10 min, use
  `ControlMaster`/`ControlPersist`, never retry-loop into a failing connection.
  Concurrent polling loops across sessions saturated sshd `MaxStartups` and
  locked everyone out of every pod.
- **Evals must be sequential.** 3-way → SIGABRT; 2-way silently corrupts (cost an
  8-pt baseline error historically).

## 8. Standing user constraints — do not violate

- **No behavioural cloning.** `--bc-weight` stays 0. Boundary clipping (`--amax`)
  is explicitly endorsed; BC is not.
- **No ensembles** at inference.
- **Metric Residual Network head** stays (IQE/QRL/Eikonal/rank-only were all
  explored and rejected — every intervention that improved the value's temporal
  ordering *lost* ~30 pts of task success, because the planner queries V at
  WM-imagined off-manifold states where the expectile-0.03 optimism is
  load-bearing).
- **egl always.**
- **Full-pool is the headline LIP number** (86.5 at amax 1.6). Held-out numbers
  are for the Dyna comparison, which needs both arms on held-out episodes.
- One shared branch across parallel sessions; commit to campaign-scoped subdirs,
  don't `git checkout` in the shared dir.
